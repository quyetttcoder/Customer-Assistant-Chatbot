# Customer Support Chatbot

A customer support chatbot that answers questions about orders and store policies. The project combines structured order data with retrieval-augmented generation (RAG) so that responses can be grounded in database records and policy documents.

The application uses the Microsoft Northwind Sample Database as demo data for customers, products, and orders. The policy documents are synthetic examples generated with AI for demonstrating policy retrieval; they are not official policies from Microsoft or a real retailer.

## Features

- Natural-language questions about products, customers, and orders using structured data stored in Supabase.
- Policy question answering using RAG with policy documents stored in Qdrant.
- OpenAI models for language generation, query-structure generation, and embeddings.
- Streaming chat responses over a WebSocket connection.
- Human-agent escalation flow that asks the user to approve or decline the transfer.
- Metadata-based restrictions intended to prevent internal database fields from being exposed to customers.

## Architecture

The project has two main applications:

- `back-end/`: FastAPI WebSocket server, LangGraph agent workflow, Supabase query tool, and Qdrant-based policy retrieval.
- `front-end/`: Next.js chat interface that communicates with the backend over WebSockets.

The backend uses the following services:

| Component | Purpose |
| --- | --- |
| Next.js | Web chat interface |
| FastAPI and WebSockets | Backend API and streaming communication |
| LangGraph and LangChain | Agent workflow and tool orchestration |
| OpenAI API | Chat completion and text embeddings |
| Supabase | Structured Northwind demo data |
| Qdrant Cloud | Vector storage and retrieval for policy documents |

## Data Sources

### Northwind Sample Database

The structured dataset is based on Microsoft's Northwind Sample Database, a demo dataset commonly used to illustrate order-processing and sales scenarios. The repository includes raw and cleaned CSV files under `back-end/data/`, including customers, orders, order details, products, categories, employees, suppliers, shippers, territories, and regions.

This is demonstration data. It should not be treated as live customer, inventory, or order information.

### Synthetic Policy Documents

The `back-end/data/policies/` directory contains AI-generated sample policy documents:

- `payment_policy.md`
- `privacy_policy.md`
- `return_and_refund_policy.md`
- `shipping_policy.md`

These documents are used to demonstrate RAG retrieval. Their contents are illustrative and do not represent official Microsoft policies or the actual policies of a production business. Review and replace them before adapting the project for real customers.

## Configuration

### Backend environment variables

Create a `.env` file in the `back-end/` directory. Do not commit this file or share its secrets.

```dotenv
OPENAI_API_KEY=your_openai_api_key

SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your_supabase_key

QDRANT_URL=https://your-qdrant-instance-url
QDRANT_API_KEY=your_qdrant_api_key
```

Use the credentials appropriate for your own services. Keep API keys private and follow your provider's security recommendations.

### Frontend environment variables

The frontend defaults to `ws://localhost:8000/ws` when `NEXT_PUBLIC_WS_URL` is not set. To configure it explicitly, create `front-end/.env.local`:

```dotenv
NEXT_PUBLIC_WS_URL=ws://your_url_path/ws
```

For a deployed HTTPS frontend, configure the corresponding secure WebSocket URL (`wss://...`) and update the backend CORS settings for the frontend origin.

## Installation and Setup

### 1. Prepare Supabase

1. Create a Supabase project.
2. Create database tables for the Northwind data that the chatbot will query. The table names and fields must match the metadata in `back-end/process_data/tables_metadata.py` and the queries generated by the backend.
3. Import the appropriate CSV data from `back-end/data/database_csv_cleaned/` into the matching tables.
4. Confirm that table and column names match the application metadata. The current query tool expects tables such as `products`, `suppliers`, `categories`, `orders`, `shippers`, and `customers`.
5. Configure the `SUPABASE_URL` and `SUPABASE_KEY` values in `back-end/.env`.

The repository provides CSV data and metadata, but database tables must be created and populated in your Supabase project before database questions can work.

### 2. Prepare Qdrant

1. Create a Qdrant collection named `Chatbot_Support_Customer`.
2. Configure the collection to support named vectors with the name `dense`, vector size `1536`, and cosine distance. This matches the `text-embedding-3-small` embedding model used by the project.
3. Set `QDRANT_URL` and `QDRANT_API_KEY` in `back-end/.env`.

The collection-creation code in `back-end/process_data/create_kb.py` is currently commented out. Create the collection with the required configuration before running the ingestion script.

### 3. Install backend dependencies

From the repository root, run:

```bash
cd back-end
python -m venv .venv
```

Activate the virtual environment.

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

On macOS or Linux:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install python-dotenv openai langgraph langchain-core websockets
```

The additional packages cover imports used by the backend that may not be explicitly listed in `requirements.txt`.

### 4. Ingest policy documents into Qdrant

The ingestion script reads Markdown files from a `policies/` directory relative to its working directory. The policy files are stored under `back-end/data/policies/`, so run the script from `back-end/data/`:

```bash
cd data
python ../process_data/create_kb.py
```

The script splits the policy documents into chunks, generates embeddings with OpenAI's `text-embedding-3-small` model, and upserts them into the `Chatbot_Support_Customer` collection.

If you run the script from another directory, update the `policies_path` in `process_data/create_kb.py` or adjust the working directory accordingly.

### 5. Start the backend server

From the `back-end/` directory, with the virtual environment activated:

```bash
uvicorn server:app --host 0.0.0.0 --port 8000 --reload
```

The WebSocket endpoint used by the frontend is:

```text
ws://localhost:8000/ws
```

Keep this terminal running while using the frontend.

### 6. Install and start the frontend

Open another terminal and run:

```bash
cd front-end
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

The frontend connects to the backend WebSocket endpoint. If you change the backend address, update `NEXT_PUBLIC_WS_URL` in `front-end/.env.local` and restart the frontend development server.

## Using the Chatbot

1. Start the backend and frontend.
2. Open the frontend in your browser.
3. Ask a question about a demo order, product, or store policy.
4. For policy questions, the assistant retrieves relevant passages from the policy documents and uses them to compose a response.
5. For order-related questions, the assistant queries the structured Northwind data through Supabase. The backend metadata describes certain customer fields as internal-only and uses customer details to help verify order ownership.
6. If the assistant offers escalation to a human agent, select **Approve** to confirm or **Deny** to continue with chatbot support.

Example questions:

- "What is the status of my order?"
- "Which products are currently in stock?"
- "What is your return and refund policy?"
- "How long does shipping take?"
- "What payment methods are supported?"

The sample dataset is not connected to a real store, so example questions should be interpreted as demonstrations rather than requests about actual purchases.

## Data Processing Utilities

The backend includes scripts for working with the CSV data:

- `back-end/process_data/preprocessing_csv.py`: inspects and processes CSV files. Review its input and output paths before running it; it expects a `database_csv/` directory relative to the current working directory.
- `back-end/process_data/tables_metadata.py`: defines table and field descriptions used by the natural-language query generation logic.
- `back-end/process_data/create_kb.py`: chunks the Markdown policy documents, creates embeddings, and uploads them to Qdrant.

The repository contains both raw and cleaned CSV directories. Import the cleaned data into Supabase unless you have reviewed the raw files and intentionally want to process them yourself.

## Troubleshooting

### The frontend cannot connect to the backend

- Confirm that the backend is running on port `8000`.
- Check that `NEXT_PUBLIC_WS_URL` points to the correct WebSocket endpoint.
- Confirm that the backend CORS configuration allows the frontend origin.
- Restart the frontend after changing environment variables.

### Database questions fail

- Verify `SUPABASE_URL` and `SUPABASE_KEY`.
- Confirm that the required tables and columns exist in Supabase.
- Check that table names and column names match `tables_metadata.py`.
- Review the backend terminal output for API or query errors.

### Policy questions return no useful results

- Confirm that the `Chatbot_Support_Customer` Qdrant collection exists and uses the `dense` named vector with 1536 dimensions.
- Confirm that policy documents were ingested successfully.
- Verify the OpenAI API key and Qdrant credentials.
- Re-run the ingestion script after changing policy documents.

### OpenAI API errors

- Verify that `OPENAI_API_KEY` is valid and that the account has access to the models used by the application.
- Check API usage limits and billing settings.

## Security and Limitations

- This project is a demo and is not production-ready without further review.
- Do not use the bundled sample data as real customer information.
- Keep `.env` and `.env.local` files out of version control.
- Review authentication, authorization, database access policies, rate limiting, logging, error handling, and secret management before deployment.
- The current backend creates an in-memory conversation checkpoint and deletes the thread when the WebSocket disconnects. Conversation state is not intended to persist across sessions.
- The human-agent escalation flow is an approval demonstration; it does not itself connect to a real support team.
- AI-generated policy documents may contain inaccurate or arbitrary terms. Validate them before using them to make business decisions.
- The current CORS configuration allows `http://localhost:3000`; update it for your deployment environment.
